# Pinned values: what they are and why

Türkçe: [../muhendislik/sabit_degerler.md](../muhendislik/sabit_degerler.md).

A **pinned value** is a number or choice fixed in code or in `src/dublaj_hatti/varsayilan.toml`: a voice id, a threshold,
a window length, a batch size, a timeout, a sample rate. Many of them look arbitrary; most are not. Each row below says
where the value lives, what it does, why it has this value and what breaks if it is changed. Engine- and stage-level
reasoning is in the other pages of this folder and in [../adr/](../adr/README.md); this page works one level lower, value
by value.

Where each value acts inside a job, stage by stage and file by file: [pipeline-flow.md](pipeline-flow.md).

**"No record"** means the reason was searched for in the project's measurement notes and was not found. It does not mean
the value is free to change: treat it as "unknown risk" and measure before and after.

## Before changing a pinned value

1. Read its row and the linked page or ADR.
2. Re-run the measurement named in "If changed" on full-length inputs (several failures only showed on long files).
3. Change the value, this page (EN + TR) and `tests/test_sabit_degerler.py` in the same change.
4. If the value affects a stage's output, bump that stage's checkpoint contract version
   ([ADR 0012](../adr/0012-stage-checkpoints-and-resume.md)); never add a silent fallback
   ([ADR 0009](../adr/0009-fail-closed-no-silent-fallback.md)).

Paths are relative to `src/dublaj_hatti/`; line numbers were taken when this page was written and may drift.

## Version pins

Package versions are locked with hashes in `requirements/*.txt` and model files with commit + SHA-256 in
`scripts/modeller.json`; the reasons for the risky ones (torch builds and Pascal kernels, Demucs 4.0.1, FFmpeg) are in
[gpu_memory_and_isolation.md](gpu_memory_and_isolation.md), [low_vram.md](low_vram.md) and
[../installation.md](../installation.md). Lock checks: `tests/test_kurulum_kilitleri.py`.

Container images for the optional local Telegram Bot API server (ADR 0018) are pinned by digest, never by a tag alone:
the ready-made community image `aiogram/telegram-bot-api@sha256:49fb5d9f…` (`yerel_sunucu.py:61`), and for the
`--kaynaktan` build the official source at commit `e3e9dd8e…` (`yerel_sunucu.py:63`) on the base image
`debian:bookworm-slim@sha256:7ff6ba31527b9e336162fa061746c366c4b2032f4d2cff2078bea43f78efe3f8` (multi-arch index,
both `FROM` lines of `scripts/telegram_bot_api.Dockerfile`; read from the Docker Hub registry on 2026-10-25). A tag
can be moved to a different image; a digest cannot. To update: read the new index digest
(`docker buildx imagetools inspect debian:bookworm-slim`), replace both lines, rebuild with `--kaynaktan`.

### Upstream-capped packages

Some transitive dependencies are pinned by an upper bound set by the package that pulls them in, not by us. Moving to a
newer version breaks the install until that upstream bound is relaxed, so Dependabot ignores only the versions above the
bound (`.github/dependabot.yml`); patch releases below it are still proposed.

| Package | Pin | Bound set by | Where | Check |
|---|---|---|---|---|
| `coqui-tts-trainer` | 0.3.x | `coqui-tts` 0.27.5: `coqui-tts-trainer<0.4.0` | `requirements/ek_tts_xtts.txt`, XTTS venv locks | `pip check` |
| `antlr4-python3-runtime` | 4.9.3 | `omegaconf` 2.3: `antlr4-python3-runtime==4.9.*` | `requirements/gpu.txt`, `cpu.txt`, Demucs extras | `pip check` |

How to try a newer version without breaking anything:

1. First check on PyPI whether a newer release of the upstream package (`coqui-tts`, `omegaconf`) removed the bound. If it
   did, the right move is to upgrade the upstream package; the dependency follows.
2. Test in a separate virtual environment and leave the installed one untouched:
   `uv venv trial && uv pip install -p trial -r requirements/<lock>.txt`, then swap only the package under test with
   `uv pip install -p trial "<package>==<version>"`.
3. If `uv pip check -p trial` reports a conflict, that version does not work with the upstream package; stop here.
4. If there is no conflict, run `pytest -m "not gpu and not slow"` and a short dub with the affected engine; compare output
   duration and audio with the previous version.
5. If the result is clean, open an issue or PR: the lock is regenerated from `requirements/*.in` (`scripts/kilitle.ps1`),
   and this table and the `.github/dependabot.yml` ignore entry are updated together.
